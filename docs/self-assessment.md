## Mental model (rubric dimension 1)

**AIDEN in one sentence:** AIDEN is Upstart13's AI app foundation: versioned `@upstart13-com/aiden-*` packages that ship auth, data, security, logging, AI, realtime and UI, plus a starter template and CLI, so an app team builds features on a hardened base instead of re-implementing it.

**The two surfaces:**

| Surface                                         | Owned by          | Changes how                                                                          | In DeskLine                                                                                              |
| ----------------------------------------------- | ----------------- | ------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------- |
| The SDK packages (`@upstart13-com/aiden-*`)     | Upstart13         | Only through `aiden upgrade` (codemods, migrations, one commit); defects go upstream | Never forked or hand-bumped; 20 defects written up in `docs/upstream-sdk-issues.md`                      |
| The app cloned from the starter by `aiden init` | The customer (us) | Edited freely: features, config, fragments, starter fixes                            | DeskLine's code, plus fixes to starter files (postinstall, `.env.example`, auth layout, compaction hook) |

**Single-train versioning:** every `@upstart13-com/aiden-*` package ships on one version number (all 2.0.1 here) and is upgraded together. `aiden-cli` resolves "latest" from `aiden-ai` and bumps every package in one step. A mixed set is a broken install: it's how duplicate `aiden-logging` copies, and the empty request context they cause, happen (`ops-diagnosis.md` §3).

**Two facts the viva checks:**

- **SSE lives in `aiden-realtime`, not `aiden-ai`.** `aiden-ai` produces the token stream (`ai.stream`); `aiden-realtime` turns it into a server-sent-events response (`createAIStreamResponse`, draft route) and consumes it in the browser (`useAIStream`, draft panel).
- **The starter is customer-owned and not on npm.** It ships inside `aiden-cli` (its `template/` folder) and `aiden init` copies it into the app. No `@upstart13-com/aiden-starter` package exists (registry: 404), so starter fixes are made in the app, and SDK defects go upstream.
